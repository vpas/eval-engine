Distributed LLM-evaluation platform

Eval Engine

A modular, distributed platform for running any model × harness × dataset × scorer at scale — with durable, queryable results and a dashboard to author, launch, monitor, and analyze every run. It is built around Inspect AI as the evaluation kernel; the platform's value-add is distributed orchestration, a ClickHouse analytics projection, and the web UI on top.

The goal

Evaluating large language models is a combinatorial problem: a model is judged by driving it through a harness (single-turn QA, multiple-choice, a tool-using agent loop…) over a dataset, then grading each output with one or more scorers (string match, a model-graded judge, programmatic code execution…). Eval Engine keeps those four concerns orthogonal — any valid combination composes — and runs the resulting work distributed, crash-safe, and resumable, persisting every sample's input, output, transcript, scores, tokens, cost, and timing for later analysis.

Compose freely

Model, harness, dataset, and scorer are independent blocks. Spans QA, multiple-choice, multi-turn agentic, LLM-as-judge, and programmatic scoring.

Run at scale

Up to 100k samples per run, fanned out over autoscaled workers coordinating through a Postgres ledger — with retries, global rate limiting, and resume.

Reproduce & analyze

A run's inputs are fully pinned by a versioned RunSpec; results land in ClickHouse for fast slicing, with the Inspect transcript viewer for per-sample drill-down.

Design principles

  • Inspect-native. Harnesses are Inspect Solvers, scorers are Inspect Scorers, and the .eval log is the source-of-truth artifact. We adopt a solved kernel and spend effort on the differentiated platform.
  • Two planes. A lightweight control plane (API + Postgres + dashboard) for humans and state; a heavy execution plane (orchestrator + autoscaled workers + gateway) for compute. They communicate only through Postgres + the ledger, so each scales independently.
  • Portable by interface. Terraform + Helm, the S3 object-storage API, vanilla Postgres, OIDC. No component is cloud-locked; the same topology retargets EKS/GKE/AKS.
  • Defer with a trigger. Everything not forced by the scale envelope is kept minimal for v1 and deferred behind a measured trigger, so the system stays as simple as the load allows.
